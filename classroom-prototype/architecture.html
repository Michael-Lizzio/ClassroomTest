Chalkboard Architecture

How the real app would be built and scaled

1. Stack & Why

Recommended Cross-Platform Approach

Recommendation: Expo / React Native with React Native Web

Use Expo for iOS and Android, with React Native Web for the web client. A single TypeScript codebase powers all three platforms. Expo's managed workflow eliminates the need to manage native builds initially, and Supabase's client libraries work seamlessly across all three targets.

Why not native? Native (Swift, Kotlin) would be faster for certain gestures and the drawing canvas, but requires maintaining three codebases and tripled development time. Expo gets us to market 3–4× faster.
Why not Next.js only? Web-only won't reach students on phones during class (low friction to join is critical). Native apps see higher adoption and perform better for real-time drawing/captions.

Backend: Supabase (PostgreSQL + Auth + Realtime + Storage + Edge Functions). No separate API server initially; Supabase handles auth, database, file uploads, and broadcasts.

2. System Diagram

Architecture Overview

Key components:

  • Clients: iOS (Expo), Android (Expo), and Web (React Native Web) all share the same codebase.
  • Supabase Auth: Anonymous sign-in for students, standard email/password for teachers.
  • PostgreSQL: Stores classes, participants, questions, notes, and board state.
  • Realtime over WebSockets: Broadcasts board drawing, teacher position, captions, and area visibility.
  • Storage: Board snapshots and lesson materials (PDFs, images).
  • Speech-to-Text: Realtime transcription of the teacher's voice (Google Cloud Speech-to-Text or Deepgram).
  • Hosting: Web app on Vercel or Netlify; mobile apps on App Store and Play Store (via Expo Application Services for CI/CD).
3. Realtime Design

WebSocket Communication

Use one Supabase Realtime channel per class session. Channel name: class:<session_id>.

Data Transport Rationale
Board drawing, teacher position, captions, area visibility Broadcast (ephemeral) High frequency, lossy OK, no need to persist
Who is online Presence (built-in) Automatic heartbeat, list of active participants
Questions, notes, board state, session state Postgres Changes Durable, auditable, late joiners fetch state

Example: Board drawing event

{ "event": "board:draw", "data": { "session_id": "bio101-ph-2024-11-07", "x": 240, "y": 180, "color": "#2d3436", "width": 3, "timestamp": 1730962800000 } }

Example: Caption event

{ "event": "caption", "data": { "session_id": "bio101-ph-2024-11-07", "text": "The light reactions occur in the thylakoid membranes", "timestamp": 1730962805000 } }

Late joiner catch-up: When a student joins mid-class, fetch the current board state (raster image + object tree) from a board_snapshots table, and recent questions from the database. Then subscribe to Realtime to get live updates.

Rate limiting & batching: Throttle drawing events to 30 Hz client-side (batch strokes within 33 ms windows) to avoid overwhelming the network. Captions and area changes send immediately.

4. Data Model

Database Schema

-- Classes (recurring) CREATE TABLE classes ( id UUID PRIMARY KEY, teacher_id UUID NOT NULL REFERENCES auth.users, name TEXT NOT NULL, description TEXT, created_at TIMESTAMP DEFAULT NOW() ); -- Sessions (one per class meeting) CREATE TABLE sessions ( id UUID PRIMARY KEY, class_id UUID NOT NULL REFERENCES classes, teacher_id UUID NOT NULL REFERENCES auth.users, join_code TEXT UNIQUE NOT NULL, started_at TIMESTAMP DEFAULT NOW(), ended_at TIMESTAMP, created_at TIMESTAMP DEFAULT NOW() ); -- Participants CREATE TABLE participants ( id UUID PRIMARY KEY, session_id UUID NOT NULL REFERENCES sessions, user_id UUID REFERENCES auth.users, display_name TEXT NOT NULL, is_teacher BOOLEAN DEFAULT FALSE, joined_at TIMESTAMP DEFAULT NOW(), UNIQUE(session_id, user_id) ); -- Questions CREATE TABLE questions ( id UUID PRIMARY KEY, session_id UUID NOT NULL REFERENCES sessions, student_id UUID NOT NULL REFERENCES participants, text TEXT NOT NULL, board_snapshot_url TEXT, marked_area JSON, answered BOOLEAN DEFAULT FALSE, pinned BOOLEAN DEFAULT FALSE, created_at TIMESTAMP DEFAULT NOW() ); -- Notes CREATE TABLE notes ( id UUID PRIMARY KEY, session_id UUID NOT NULL REFERENCES sessions, title TEXT NOT NULL, content TEXT, order_index INT, created_at TIMESTAMP DEFAULT NOW() ); -- Board state (persisted for late joiners) CREATE TABLE board_snapshots ( id UUID PRIMARY KEY, session_id UUID NOT NULL REFERENCES sessions, image_url TEXT NOT NULL, objects JSONB, area_layout TEXT, visible_areas JSONB, created_at TIMESTAMP DEFAULT NOW() ); -- Transcripts (for captions & record) CREATE TABLE transcript_segments ( id UUID PRIMARY KEY, session_id UUID NOT NULL REFERENCES sessions, text TEXT NOT NULL, timestamp_ms INT NOT NULL, confidence FLOAT, created_at TIMESTAMP DEFAULT NOW() );

Row Level Security:

  • Students see only visible board areas (via visible_areas in session).
  • Only the teacher sees all questions; students see only their own questions and marked-answered ones.
  • Board snapshots accessible to all session participants.
  • Transcripts visible to all, archived after session ends.
5. Joining

Frictionless Student Entry

  • Join codes: 6-character alphanumeric (e.g., BIO101-PH). Student enters it or scan QR code.
  • QR deep links: QR encodes a universal link: chalkboard.app/join?code=BIO101-PH. On iOS it opens the app; on Android it opens the app or web; on desktop it opens the browser.
  • Anonymous sign-in: No account needed for students. System creates an anonymous Supabase user, then stores their display name in the participants table.
  • Link expiry: Join codes expire 24 hours after class ends. Teachers can manually revoke.
// Joining flow (pseudocode) const joinClass = async (joinCode, displayName) => { // Create anonymous user const { data } = await supabase.auth.signInAnonymously(); // Find session by join code const { data: session } = await supabase .from('sessions') .select('*') .eq('join_code', joinCode) .single(); // Add participant await supabase.from('participants').insert({ session_id: session.id, user_id: data.user.id, display_name: displayName }); // Subscribe to Realtime subscribeToSession(session.id); };
6. Live Transcription

Microphone to Captions

Path: Teacher's microphone → streaming speech-to-text → captions broadcast → all clients display.

Providers & trade-offs:

Google Cloud Speech-to-Text
~$0.024 per 15 sec, 300 ms latency, very accurate. Need to manage audio streaming.
Deepgram
$0.0043 per min, 400 ms latency, simple API, excellent accuracy. Recommended.

Implementation: Teacher's browser captures audio via WebRTC or native audio API, sends to Deepgram real-time API, receives text, broadcasts via Realtime Broadcast channel. Clients render captions in the Present mode overlay.

Storage: Save transcript segments to transcript_segments table for post-class review and accessibility compliance (FERPA).

7. Hosting & Deployment

Getting to Production

  • Web app: Deploy to Vercel or Netlify (automatic on every push to main). Use environment variables for Supabase URL and API keys.
  • Supabase plan: Start with the Free plan (up to 50,000 monthly active users, 5 GB storage). Scale to Pro ($25/mo) or Custom when you hit limits or need higher rate limits on Realtime.
  • Edge Functions: Use for QR code generation, email notifications, and moderation. Supabase Edge Functions (Deno) run for free within rate limits.
  • Mobile CI/CD: Use Expo Application Services (EAS) for iOS and Android builds. Runs in the cloud, no local Xcode/Android Studio needed. ~$300/mo for 1,000+ builds.
  • Environments: Staging (staging-db) and production (prod-db). Mobile apps can point to either via config.
8. Scale, Cost & Limits

Numbers that Matter

One class of 30 students:

  • ~300 board drawing events/sec (30 participants × 10 strokes/sec).
  • ~1 KB per Realtime message → 300 KB/sec = ~1.08 GB/hour.
  • ~30 Postgres writes/min (questions, notes).
  • ~120 concurrent WebSocket connections.
  • Cost: Negligible on Free plan (included in Supabase limits).

1,000 classes running at once (~30,000 students):

  • ~30,000 concurrent WebSocket connections → Supabase Real time can handle this on Pro plan.
  • ~9 million Realtime messages/hour → ~$0.50/hour at scale (Pro plan).
  • ~50,000 Postgres writes/hour → Well within Pro limits (10,000 queries/sec).
  • Cost: ~$25/mo (Supabase Pro) + $10/mo (Vercel) + $50/mo (transcription) = ~$85/mo base.

What breaks first: Realtime bandwidth (switch to a dedicated socket server if >100,000 concurrent). Then Postgres connections (add pgBouncer). Then storage (archive old board images to S3-compatible storage).

9. Security & Privacy

Protecting Students

  • COPPA (Children's Online Privacy Protection Act): If any users are <13, require parental consent before collecting personal info. Disable analytics for minors; no ads or tracking.
  • FERPA (Family Educational Rights and Privacy Act): Treat student questions and session data as "educational records." Encrypt at rest and in transit. Allow parents to request deletion of their child's data.
  • Data retention: Delete session recordings 90 days after class ends, unless teacher opts to archive. Student questions deleted 1 year after session.
  • Moderation: Flag questions with certain keywords (admin review). Teachers can delete inappropriate questions immediately.
  • Auth: HTTPS only. Session tokens expire after 24 hours idle. Require teacher login (email + password or SSO via Google/Microsoft for school integrations).
10. Build Plan

Phases: MVP → v1 → Scale

Phase 1: MVP (8 weeks)
  • Expo app + React web
  • Supabase Auth (anonymous students, email teachers)
  • Whiteboard (drawing only, no areas or hidden sections)
  • Questions inbox (text only, no snapshots)
  • No transcription or Present mode
  • Manual QR codes (static image)
  • Deploy to Vercel + TestFlight/internal testing
Phase 2: v1.0 (10 weeks)
  • Board areas (whole/halves/2×2 grid)
  • Question snapshots (screenshot of marked area)
  • Dynamic QR code generation
  • Basic transcription (Google Cloud Speech)
  • Present mode (slides + live captions)
  • Lesson notes (push to board)
  • Public beta (App Store + Play Store)
Phase 3: v1.1 (6 weeks)
  • Teacher authentication (Google/Microsoft SSO)
  • Class roster & attendance
  • Student profiles + avatars
  • Archive & replay (watch past class)
  • Analytics dashboard
